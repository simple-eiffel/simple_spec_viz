## TASK STRUCTURE

### Layer 1: Foundation (Data Models) - 4 Tasks

**TASK 1: SPEC_VIZ_RESULT**
- Immutable data class (XOR pattern: success OR error)
- 3 creation methods, 3 query methods
- 8 acceptance criteria (invariants, XOR, void-safety)

**TASK 2: SPEC_STATE & SPEC_TRANSITION**
- State: ID, label, initial/final flags, entry/exit actions
- Transition: source/target IDs, event, guard, action
- 15+ acceptance criteria (preconditions, frame conditions, mutually-exclusive)

**TASK 3: SPEC_SCREEN, SPEC_WIDGET, SPEC_REQUIREMENT**
- Screen: containers for widgets (grid-based layout)
- Widget: type, label, x/y/width/height
- Requirement: ID, description, traceability links
- 12+ acceptance criteria (collections, references, traceability)

---

### Layer 2: Container & Loader - 2 Tasks

**TASK 4: SPEC_DOCUMENT**
- Root container: states, transitions, screens, requirements, traceability matrix
- 10 query methods (state_by_id, initial_state, final_states, transitions_from, etc.)
- 5 model queries (MML_SET for states, screens)
- 15+ acceptance criteria (no duplicates, lookups, invariants)

**TASK 5: SPEC_LOADER**
- JSON parser with schema validation
- Uses simple_json library
- Error handling: file not found, invalid JSON, missing fields, broken refs
- Result pattern: Void on error with last_error set
- 12+ acceptance criteria (validation, error messages, format checking)

---

### Layer 3: Generators - 4 Tasks

**TASK 6: GRAPHVIZ_ADAPTER**
- Utility adapter isolating simple_graphviz dependency
- Renders DOT to SVG, handles timeouts and errors
- Runtime GraphViz check with install instructions
- 8+ acceptance criteria (rendering, error handling, availability)

**TASK 7: STATE_DIAGRAM_GENERATOR**
- Builds DOT representation of state machine
- Initial state (●), final states (◉), transitions with guards/actions
- WCAG 2.1 Level AA accessibility (12pt+ font, 4.5:1 contrast, no overlaps)
- 14+ acceptance criteria (diagrams, marks, labels, accessibility, performance)

**TASK 8: SCREEN_MOCKUP_GENERATOR**
- Text-based SVG generation (no external rendering)
- One SVG per screen with widgets positioned in grid
- Widget types labeled, positions rendered
- 10+ acceptance criteria (per-screen mockups, layout, labels)

**TASK 9: TRACEABILITY_REPORT_GENERATOR**
- Markdown matrix: Requirement | Realized In | Implementation Path
- Gap detection (unimplemented requirements, undocumented states)
- Automated diff verification (element count matching)
- 8+ acceptance criteria (format, gaps, traceability links)

---

### Layer 4: Facade - 1 Task

**TASK 10: SIMPLE_SPEC_VIZ**
- Single entry point coordinating all loaders and generators
- Public API: load_from_file, load_from_json, generate_*, generate_all
- generate_all: batch operation (state diagram + all mockups + traceability)
- save_to_file helper for writing outputs
- 15+ acceptance criteria (initialization, delegation, batch generation, error handling)

---

### Layer 5: CLI Integration - 1 Task

**TASK 11: CLI Tool**
- Command: `simple_spec_viz visualize <spec.json> [--output <dir>]`
- Argument parsing, validation, error handling
- Exit codes: 0=success, non-zero=error
- Error messages formatted for human readability
- 10+ acceptance criteria (parsing, validation, error messages, exit codes)
