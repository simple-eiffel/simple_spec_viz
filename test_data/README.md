# Simple Spec Viz Test Data

This directory contains test inputs and generated outputs for the simple_spec_viz end-to-end test suite.

## Structure

```
test_data/
├── inputs/              # GUI specification JSON files (test inputs)
│   ├── devkit_cli.json          # DevKit CLI state machine spec (4 states, 5 transitions)
│   └── devkit_windows.json      # DevKit Windows GUI spec (5 states, 8 transitions, 5 screens)
└── outputs/             # Generated visualization outputs (SVG + markdown)
    ├── state_machine.svg        # State transition diagram
    ├── SCR-001.svg through SCR-005.svg  # Screen mockups
    └── traceability.md          # Requirements traceability matrix
```

## Test Inputs

### devkit_cli.json
- **Source:** `/d/prod/simple_spec_viz/samples/devkit_cli.json`
- **Purpose:** Original test specification for DevKit CLI application
- **Content:** 4 states (idle, processing, complete, error), 5 transitions, 4 screens
- **Requirements:** Base64, Hash, UUID, Timestamp, JWT operations

### devkit_windows.json
- **Source:** Generated via `eiffel-gui-ux` skill from DevKit specification
- **Purpose:** Windows GUI UX version of DevKit utility suite
- **Content:** 5 states, 8 transitions, 5 screens, 26 widgets
- **Screens:**
  1. Main Utility Panel - Tabbed interface (Base64, Hash, UUID, Timestamp, JWT)
  2. Processing View - Progress indicator
  3. Success Result View - Result display and copy
  4. Error View - Error details and retry
  5. Settings Panel - Application preferences

## Generated Outputs

### state_machine.svg
- SVG diagram showing all states and transitions
- Generated by simple_graphviz from specification
- Includes state labels, transitions, and event names

### Screen Mockups (SCR-*.svg)
- SVG visualization of each screen/window layout
- Generated for each screen in the specification
- Shows widget positions, labels, and types
- Uses GraphViz record shapes for layout

### traceability.md
- Markdown report linking requirements to states and screens
- Tables showing:
  - States → Screens mapping
  - Requirements → States coverage
  - Coverage summary and statistics

## End-to-End Test Pipeline

The `test_end_to_end_file_generation` test validates the complete pipeline:

```
1. Load specification from JSON file (test_data/inputs/*.json)
   ↓
2. Parse states, transitions, screens, widgets, requirements
   ↓
3. Generate outputs:
   - state_machine.svg (via STATE_DIAGRAM_GENERATOR)
   - SCR-*.svg (via SCREEN_MOCKUP_GENERATOR)
   - traceability.md (via TRACEABILITY_REPORT_GENERATOR)
   ↓
4. Write all files to test_data/outputs/
   ↓
5. Verify file creation and content
```

## Adding More Test Inputs

To add a new specification for testing:

1. Create new JSON file in `test_data/inputs/`:
   ```bash
   cp existing_spec.json test_data/inputs/new_spec.json
   ```

2. Alternatively, generate from eiffel-gui-ux:
   ```bash
   /eiffel.gui-ux generate windows my_spec.md --output-dir test_data/inputs/
   ```

3. Run end-to-end test:
   ```bash
   cd /d/prod/simple_spec_viz/bin
   ./simple_spec_viz_test_app.exe
   ```

4. Outputs automatically generate to `test_data/outputs/`
